# 개발팀 — 확정 조항

대표 발화는 **원문 그대로** 둔다. 맞춤법도 고치지 않는다. 해석은 그 아래 따로 쓴다.
둘을 섞지 않는다 — 관리자의 요약이 곧 오염이다.

제리(총괄실 외부감사)가 승인 요청을 대조할 때 이 파일을 원문으로 삼는다.

---

## 2026-09-02 — 개발팀의 프로젝트는 ppanam 자체

**대표 원문** (설계 점검 요청, 항목 6·7)

> 개발팀은 현재 이 작전실이 진짜 커맨드센터, 우리의 헤드쿼터가 될 수 있도록, 그 안에서 전체 팀 구조가 돌아갈 수 있도록 만들어주면 좋겠어. UI랑 UX도 당연히 개선해야하고.

> 팀 : 총괄 (나 대리, 나 대신해서 결정 및 나한테 요약 보고, 필요시 호출 등) / 개발팀(개발2,감사1) / 디자인팀(디자인2,감사1) / 마케팅팀(실무자 / 내부감사 / 외부감사) / 경영팀(현경영재무팀) -> 구성 미완, 제안필요 / CS팀 (구성 미완 -> 제안 필요)

**해석** (톰 대신 하네스 세션이 적음 — 총괄실이 열리기 전)

개발팀의 로드맵 M1~M6 (`roadmap.json`)은 이 원문과, 같은 날 대표가 승인한 설계 점검에서 나왔다.
디자인·경영·CS 는 대표 원문에 "구성 미완, 제안 필요"라 돼 있고, 설계 점검에서 **보류**로 승인됐다.

## 2026-09-02 — 승인 체인의 흐름

**대표 원문** (설계 점검 요청, 항목 3)

> 내가 자리를 비우더라도 중요한건 일단 승인요청 컨펌요청 걸어놓고 다른 작업, 큰 목표를 위해 달릴 수 있어야해. 그리고 커밋이나 푸시를 일정 수준까지 할 수 있는 관리를 톰과 제리가 하는데, 각 팀의 실무자 -> 톰에게 컨펌요청 -> 톰과 제리가 같이 승인여부 판단 -> 실제 푸시까지 허용 -> 필요시 다음미션 제공 이런식으로 자동으로 돌아가야해

**해석**

등급 A(실무 혼자) · B(톰+제리 — 푸시까지) · C(대표만). 원문의 "실제 푸시까지 허용"이 B 의 상한이다.
메인 병합·컷리스트·로드맵·외부 발송·인격 수정은 원문에 없으므로 C 로 뒀다 — 대표가 정한다.

외부감사(제리·레오·다니엘)는 불러야 오는 감사역이 아니라 방의 말을 전부 듣고, 이름이 불리면
답하고, 조용하면 끼어드는 참여자다. 판정은 시킬 때만이다. 이 요구는 설계 점검(M1~M6)에
마일스톤으로 들어가지 않았다 — 하네스의 누락이다. 로드맵에 넣는 것은 C 등급이라 대표가 정한다.
장치는 `server/responder.mjs` · `bus/outside.mjs --talk/--lull`. Fable 감사(2026-09-02) REVISE 를
반영한 뒤 연결한다.

## 2026-09-13 — 재정비 결정 열셋 (대표가 버튼으로 답함, 독립검수 세션이 옮겨 적음)

1. AGENTS.md·.codex 복사본 — 지운다. 등급 A, 테라가 라운드 안에서.
2. deny 규칙 — 잠근다. 가드가 끝나면 독립검수가 카드를 주고 대표가 저장소 루트에서 실행한다.
3. 픽셀 도구 allow 두 줄 — 주지 않는다. 기한 없음.
4. 경영재무 이름 — 팀장 유진(36, 한국, 회계사 출신, 숫자 앞에서 냉정) · 감사 노라(31, 노르웨이, 근거 없는 숫자를 제일 싫어함) · 바깥눈 빅터(41, 독일, codex, 무뚝뚝하지만 틀린 계산은 반드시 잡음). 인격 파일은 G1 첫날.
5. 3D 모델 생성 서비스(Meshy 등) — 쓰지 않는다. PixelLab 도 탈락. 캐릭터는 있는 2D 그림을 빌보드로, 건물은 Unity 기본 도형과 그린 텍스처로.
6. 비용 상한 — 침묵 차례 방당 시간당 30, 왕복 3회, 마을 하루 60회(계획 15·마주침 30·일지 15), 팀장 모델 opus 유지. 셋 다 확정. 한도를 넘으면 마을 턴부터 건너뛴다.
7. 주말·저녁 화면 — 삶 트랙의 첫 조각(아침 계획·산책·저녁 일지의 위치 이동)을 새 세계보다 먼저 지금 캔버스 마을에 붙인다. 대본 루틴은 쓰지 않는다.
8. 팀장 모델 — opus 유지(6번에 포함).
9. 본책 반영 — 보호 브랜치를 원격 기본 브랜치로 고침 → 방 밖 16커밋을 레오가 사후 감사해 PASS → 관제탑 C 카드로 대표가 승인. 그 전엔 병합하지 않는다.
10. 세계 엔진 — 비교표(남는 것·버리는 것·폰 성능·배포·한글·첫 실물까지 며칠)를 본 뒤 정한다. 기준 기기는 Android + Chrome.
11. 세 팀 킥오프 — 마케팅(15인 바이블·관계도·세계관)은 G1 과 같은 날 바로. 디자인·개발은 엔진 결정 뒤. 디자인 로드맵의 픽셀 마일스톤은 컷 리스트로.
12. 마을 발언 예산 — 6번과 같음.
13. 화면 — 탭 넷 유지 + 용어를 대표 말로 + 첫 화면에 "내가 할 일" 블록. 캔버스 마을 최소 패치(휠·핀치 줌, 급한 사건 달리기 2배, 배율·재생 속도 라벨 구분, 카드에 어제 일지 한 줄)는 지금. 그 외 그림·연출 추가 금지, 버그 수정만. 새 세계가 붙을 때 재편 검토.
14. 레오 — 명백한 것은 REVISE 세 번 없이 바로 FAIL 을 낼 수 있다. FAIL 이면 방이 멈추고 대표만 푼다.
15. "인격 최우선 · 회차와 압축을 넘는 정체성 연결고리" — 인수인계 문서의 기록을 대표 원문으로 인정한다. 순서는 인격 → 계획표 미해결 → 그림.
16. 세계 엔진 — Three.js(브라우저). 비교표(계획 6판 부록)를 보고 대표가 결정. 지금 마을의 서버 계약·연출·재생·카드 코드는 그대로 두고 그리기 층만 교체한다. Unity 는 3D 모델 결정이 뒤집힐 때 다시 본다. 디자인·개발 킥오프는 이 결정으로 열린다.
17. 턴 상한 — `server/session.mjs` 의 15분 `TURN_TIMEOUT` 이 일하는 중인 테라를 잘랐다(R13, 03:37 지시 → 03:51 까지 편집 중 → 03:52 "응답하지 않아" 로 세션 종료). 가드 8번으로 넣는다: 타이머는 턴 시작이 아니라 마지막 도구 호출·스트림 이벤트에서 다시 재고, 진짜 무응답만 죽인다. 테라가 이번 라운드에서.
18. R13 닫기 — 레오 PASS 뒤 `-v PASS` 가 아니라 요약만으로 닫는다. `-v PASS` 는 로드맵 M1(승인 체인 실물 1건)을 pass 로 찍는데 실물은 G2 에서 나온다. "정식 흐름 → roadmap pass" 시험은 `round.mjs check` 의 임시 방 결과로 갈음.

② **폴백(원칙 4) — "기본이 실패하면 누가 인계받나".** 오늘 codex 계정 하나가 끊겨 다섯 팀이 다 섰다. 손으로 Gemini 로 옮겨 풀었지만 **어디에도 적혀 있지 않았다.** 외부 감사 자리마다 대신할 엔진을 미리 적는다. 빈칸으로 두지 않는다 — 없으면 "대표께 올림" 이라고 쓴다.
