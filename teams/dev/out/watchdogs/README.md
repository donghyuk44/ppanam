# 하네스가 밤새 돌린 임시 시계들 — 참고용

2026-09-13 밤 ~ 09-14 새벽, 독립검수가 대표가 자는 동안 돌린 것. **이건 임시방편이고, 개발 M6 의 "밑바닥 막힘"(`where: infra`)이 진짜다.** 진짜가 들어오면 이건 끈다.

## nightwatch.mjs — 밤 시계
2분마다 `/api/boot` 을 읽고, 라운드가 열려 있는데 **5분 넘게 조용하고 아무도 일 안 하는 방**의 실무를 이름으로 불러 깨운다.

지키는 것 넷 (다 실패해 보고 배운 것):
- **틱마다 무조건 한 줄 기록.** 깨울 때만 적었더니 안 도는 건지 할 일이 없는 건지 못 갈랐다
- `conductor.outsideBusy` 를 busy 로 친다 — codex 가 도는 3~7분 동안 방이 조용해 보인다
- 같은 방을 다시 깨우기 전 8분 쉼
- 말은 **이름으로 시작**한다 — 사회자가 시스템 발언의 첫머리 이름만 본다

## diskwatch.mjs — 디스크 시계
20분마다 25분 넘은 `cdp-profile-*` 과 한 시간 넘은 `bash-edit-diff` 를 치우고 빈 자리를 적는다. 3G 아래면 경고.

**왜 필요했나**: 화면 찍을 때마다 헤드리스 크롬이 임시 프로필을 만드는데 안 치워서 **211개 11GB** 가 쌓였다. 낮에 개발 방이 멈춘 원인 중 하나.

## village-shot.mjs — 3D 화면 찍기
헤드리스 크롬으로 마을·회사를 파일로 찍는다. **GPU 없이 3D 를 그리려면 이 세 깃발이 필요하다** (테라가 알려줌):
`--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`

인자: `SP W H zoom name port [clock] [scene]` — 예) `node village-shot.mjs /tmp 412 915 "작게" out 9601 "15" "회사"`

**짚을 것**: 시계 고르는 칸을 찾을 때 "15" 로 찾으면 다시보기 목록의 "R15" 를 잘못 집는다. 지금 값이 "실제 시각" 인 select 만 고른다.
**그리고 끝날 때 자기 임시 프로필을 지운다** — 이게 없어서 11GB 가 쌓였다.

## 다섯째 실수 — 되살릴 때 환경변수를 빼먹었다 (09-14 새벽 2시 33분)

시계 둘의 기록 경로는 코드에 없고 환경변수에 있다 — `NW_LOG`, `DW_LOG`.
그걸 빼고 되살렸더니 `fs.appendFileSync(undefined, …)` 가 던지고, `say()` 의 `try/catch` 가 그걸 그대로 삼켰다.
**프로세스는 살아 있는데 기록이 한 줄도 안 남는 상태**가 됐다 — 첫째 실수("깨울 때만 기록해서 안 도는 건지 할 일이 없는 건지 몰랐다")와 똑같은 모양이다.

되살리는 법은 반드시 이렇게:

```
NW_LOG="<경로>/nightwatch.log" nohup node nightwatch.mjs >/dev/null 2>&1 &
DW_LOG="<경로>/diskwatch.log"  nohup node diskwatch.mjs  >/dev/null 2>&1 &
```

되살린 뒤 **5초 기다렸다가 기록 끝을 본다.** "다시 시작" 줄이 안 보이면 안 붙은 것이다.

## 시각은 우리 시각으로 (결정 101)

둘 다 `toISOString()` 으로 찍고 있었다 — 세계표준시라 우리보다 아홉 시간 빠르다.
새벽 2시 일을 오후 5시로 적고 있었고, 나도 그 숫자를 그대로 읽어 방에 말했다.
지금은 `new Date().toLocaleTimeString("sv-SE",{timeZone:"Asia/Seoul"})` 로 `02:34:17` 처럼 찍는다.
**파일에 저장하는 값(`log.jsonl` 의 `ts`)은 세계표준시 그대로 둔다.** 보여 줄 때만 바꾼다.
