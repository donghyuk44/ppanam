# 결정 187·188 — 서버 시간값 목록 (솔라, 2026-09-16)

대표 09-16 16:5x~17:0x: "몇 시에 한다고 정해진 거 다 파기해라", "모든 시간 관련된 거 다 폐기해." 잣대(나리
16:5x): 사람을 부르는 시각·길이는 "무엇이 되면"으로, 연결 끊김·재시도 같은 기계 안전 시간값은 목록으로
먼저 올린 뒤 손댄다. 이 문서는 그 목록 — 코드는 아직 안 고쳤다.

## 먼저 하나 정정

레오가 33회차 PASS 문에서 "O4(아침 한 장 자동 생성)가 c7dd8ba·80b7a97 로 이미 개편됐다"고 썼는데, 두
커밋을 열어 보니 **경영팀 문서(finance)** 와 **계약 문서(docs/event-schema.md) 한 문단**만 고쳤다 —
개발팀 서버 코드(`server/nightly.mjs`)의 `MORNING_OFFSET_MS`(06:30 고정)는 그대로다. 테라도 방에서
"아침 한 장 06:30·순찰 15분·감사 대기 30분은 솔라가 코드 고칠 때 맞추는 게 맞다"고 이미 말했다 — 아직
안 된 일이 됐다고 판정문에 실렸다는 것만 짚어 둔다. 33회차를 다시 여는 얘기는 아니다.

## A — 사람을 부른다(무엇이 되면 으로 바꿀 것)

| 값 | 지금 | 어디 | 바꿀 안 |
| --- | --- | --- | --- |
| `MORNING_OFFSET_MS` | 06:30(고정 시각) | server/nightly.mjs `morningDueDay` | 대표님이 리포트 탭을 열 때 그날 장이 없으면 그 자리에서 만든다(요청 시 생성) — 서버가 먼저 시각을 재지 않는다 |
| `ROADMAP_PROPOSAL_MS` | 10분 | server/conductor.mjs ㉡ | "로드맵 전부 pass(idle)" 상태 자체가 조건 — 이미 상태 기반이라 길이만 없앨 수 있는지 볼 것. 제안 카드가 없으면 표에 올리는 시점을 "다음 틱"으로 당기면 길이 개념이 사라짐 |
| `ROUND_SILENT_MS` | 20분 | server/conductor.mjs ㉢ | 침묵 자체가 "지속 시간" 개념이라 완전한 무-시간화는 어렵다 — 자리(솔라 O1 `wait --until`)가 있으면 그 회차는 건너뛰고, 없는 회차는 "사건 0" 을 매 틱 보는 쪽으로(첫 사건 없이 몇 틱 지나면) 재설계가 필요. **대표님 판단 필요** — 침묵 감시를 없애면 정말 조용한 회차를 아무도 못 챙긴다 |
| `CLOSE_REMINDER_MS` | 20분 | server/conductor.mjs ㉤ | "판정 완료 note + 완료 조건 통과" 상태가 이미 조건 — 재촉 없이 그 상태가 되는 즉시(다음 틱) 닫으라고 하면 길이 없앨 수 있음 |
| `DELEGATE_DECIDE_MS` | 40분 | bus.mjs D4 | "위임 판정이 남아 있으면"(leftOf 에 위임 대상이 남은 pending) 자체가 조건 — 마감 개념(초과 40분)만 빼고 "밀린 지 오래" 를 없애면 매 틱 알리게 돼 시끄러워진다. **대표님 판단 필요** |
| `PROXY_WAIT_MS` | 10분 | bus.mjs (대리 결정 후보) | "대표가 답을 안 한 채 이 항목이 남아 있으면" 자체가 조건 — 길이(10분)를 없애면 대표가 보기도 전에 대리 후보가 된다. **대표님 판단 필요** |
| `AUTO_VERDICT_MS` | 10분 | server/conductor.mjs | 말로 부른 판정(asksVerdict)을 듣고도 10분 안 열리면 자동 소집 — "청했는데 안 열렸으면" 이 조건, 길이는 기계가 못 기다리는 최소한의 여유. **대표님 판단 필요** |
