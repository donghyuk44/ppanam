# T2 — "회차 닫혀도 세션을 버리지 않는다" 가 CLAUDE.md 와 부딪힌다

## 무엇을 시켰나

라운드가 같은 마일스톤으로 자동 이어열릴 때(커밋 `9840773`, "같은 단계면 회차 자동 이어열기")
`closeRound()` 가 직전 세션을 죽였다가 곧바로 그 자리를 위해 새 세션을 띄우는 낭비가 생긴다
(실측 하룻밤 22번). "회차가 닫혀도 세션을 안 버린다"로 이걸 없애되, CLAUDE.md 의 "AI 컨텍스트는
라운드마다 비운다" 는 살려 두라는 지시였다.

## 코드로 확인한 경로

`endRound(team, opts)` (`bus/bus.mjs`, 커밋 `9840773` 로 추가된 블록, `bus/bus.mjs` 1611~1622줄
언저리)는 **자기 안에서** 다음 조건이면 이미 다음 라운드를 연다:

```
if (!milestonePassed && !next && state.milestone) {
  const stillOpen = (...).some((m) => m.n === state.milestone && m.status === 'now');
  if (stillOpen) startRound(team, { topic: state.topic ?? null });   // 다음 라운드가 여기서 이미 열림
}
```

그런데 `server/session.mjs` 의 `closeRound()` 는 그 사실을 모르고 그대로 이어간다:

```js
const n = endRound(team, opts);   // ← 여기서 이미 다음 라운드가 열려 있을 수 있다 (자동 이어열기)
reset(team);                      // ← 그래도 무조건 죽이고 id 를 버린다
```

`reset(team)` 은 `stopTeam(team)`(모든 자식 프로세스 kill) + 모든 자리 `forgetId`(다음 spawn 이
`--resume` 없이 완전히 새 프로세스로 뜸)를 한다. 자동 이어열기로 이미 열린 다음 라운드는 곧
누군가의 차례를 필요로 하므로, 방금 죽은 프로세스가 거의 즉시 다시 뜬다 — 이게 실측된 낭비다.

`opts.next`(결정 25, `--next` 로 명시적으로 잇는 경로)도 같은 모양이다: `closeRound()` 안에서
`reset(team)` 을 부른 **다음에** `startRound(team, opts.next)` 를 부른다 — 여기도 죽인 자리를
바로 다시 쓴다.

## 왜 "세션을 안 버린다" 와 "AI 컨텍스트를 라운드마다 비운다" 가 사실 같은 축인가

`reset(team)` 위의 주석이 정확히 이걸 말한다:

> 비워지는 건 AI 컨텍스트뿐이다 (CLAUDE.md). id 를 남겨두면 다음 라운드가 지난 라운드 대화를
> 통째로 안고 시작한다.

세션 id 를 남기면 다음 spawn 이 `--resume <id>` 를 쓰고, claude CLI 는 그 id 아래 쌓인 대화를
그대로 이어받는다. "세션을 버리지 않는다"는 것이 실제로 뜻하는 바가 (a) 프로세스를 안 죽이거나
(b) id 를 안 버리는 것 중 하나인데, 이 저장소의 세션 모델에서는 **둘 다 곧바로 "지난 라운드
대화를 통째로 안고 시작"과 같은 말이다.** 프로세스 자체가 대화 상태를 들고 있고(`spawnFor` 가
매 라운드 새 시스템 프롬프트를 `--append-system-prompt` 로 한 번만 박아 넣는다 — 도중에 못
바꾼다), id 는 그 상태를 가리키는 손잡이일 뿐이다. 프로세스를 살려 두거나 id 를 남기는 어떤
방법을 쓰든, 다음 라운드는 이전 라운드의 대화를 그대로 이어받는다 — 이건 CLAUDE.md 표가
못박은 "AI 컨텍스트 | 라운드마다 비운다" 를 정면으로 어긴다.

이 규칙에 "같은 마일스톤으로 자동 이어열리면 예외" 라는 조항은 **어디에도 없다**:
- CLAUDE.md 표는 조건 없이 "라운드마다 비운다"고만 쓴다.
- `reset()` 코드 주석도 조건 없이 같은 말을 한다.
- 일지 설계 자체가 "라운드가 바뀌고 컨텍스트가 비워져도 다음 세션이 이 문단을 읽고 '어제의 나'
  를 잇는다"(`closeRound()` 위 주석, `journalAll()` 위 주석)는 전제로 짜여 있다 — 즉 라운드
  경계를 넘어 대화가 아니라 **일지 한 문단**으로만 이어지게 설계한 것이 지금 구조다.
- `docs/cases.md` 를 가리키는 주석("AI티는 리셋에서 난다")도 리셋을 사고가 아니라 설계 의도로
  적어 뒀다.

자동 이어열기(커밋 `9840773`)는 "같은 마일스톤이니 라운드를 손으로 다시 여는 수고를 없애자"는
**진행 절차상의 편의**였지, "같은 마일스톤이면 컨텍스트도 이어도 된다"는 결정이 아니었다 —
커밋 메시지에도 그런 근거는 없다. 이 둘을 같다고 보고 reset 을 건너뛰면, 절차 편의를 위해
붙인 코드가 조용히 컨텍스트 계약까지 바꾸게 된다.

## 그래서 손대지 않은 것

`closeRound()`·`reset()`·`stopTeam()`·`forgetId()` 의 동작은 그대로 두었다. 자동 이어열기
경로든 `--next` 경로든, 다음 라운드로 넘어갈 때는 지금처럼 세션 id 를 버리고 새 프로세스로
띄운다.

## 컨텍스트 계약을 건드리지 않고 실제로 줄일 수 있는 것 (참고 — 이번 작업 범위 밖)

- **프로세스 기동 비용은 이미 T4 로 일부 줄었다.** `assemblePrompt` 의 책장 절(결정 116 ③,
  이번 커밋)이 인격 바로 뒤에 붙어 "안 변하는 앞부분"이 팀·자리마다 고정된 문자열이 됐다 —
  매 라운드 새 프로세스라도 `--append-system-prompt` 앞부분이 똑같으면 모델 쪽 프롬프트
  캐싱이 그 구간을 다시 안 씹는다. 이건 대화 연속성이 아니라 "같은 문장을 다시 안 읽는다"는
  것이라 컨텍스트 계약과 안 부딪힌다.
- **남은 것은 순수 프로세스 kill→spawn 왕복 비용**(claude CLI 기동 시간)이다. 이건 라운드마다
  구조적으로 필요한 비용이고(컨텍스트를 지우려면 프로세스를 새로 띄우는 것 말고 이 코드베이스에
  다른 길이 없다), 없애려면 "라운드를 더 크게 묶어 전환 횟수 자체를 줄인다"는 로드맵/절차
  쪽 결정이 필요하다 — `bus/bus.mjs`(`endRound`)와 `teams/<팀>/roadmap.json` 의 몫이라
  이번 작업(`session.mjs` 만 건드리는 범위) 밖이고, 다른 사람이 그 파일들을 동시에 고치고
  있어 손대지 말라는 지시도 있었다.
- 대표가 "자동 이어열기 == 컨텍스트 연속"으로 판단을 바꾸고 싶다면, 그건 CLAUDE.md 표 자체를
  고치는 결정이다 — 코드가 알아서 정할 일이 아니다.
