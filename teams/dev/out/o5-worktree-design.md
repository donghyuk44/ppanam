# O5 — 자리별 작업 트리 설계안 (솔라, 구현 아님 — 결정은 나리·세라)

## 문제 (독립검수 C-6 실측)

지금은 모든 자리(테라·솔라·헨리·클레멘타인·유진·노라 …)가 **같은 작업 트리 하나**를 공유한다.
`git add <내 파일들>` 로 골라 커밋해도, 같은 순간 다른 자리가 같은 트리에 쓴 파일이 섞여 들어간다 —
오늘만 세 번(예: d61339a 에 솔라 T3 가 섞임, 5c29409 계열 등). 커밋 메시지는 내 작업만 말하는데
실제 diff 엔 남의 파일이 낀다 — 감사가 "이 커밋이 뭘 했나"를 못 믿게 된다.

## 이미 있는 것 — 하네스 도구

이 세션(들)이 도는 Claude Code 하네스에 `EnterWorktree`/`ExitWorktree` 도구가 이미 있다 —
`.claude/worktrees/<이름>/` 에 새 브랜치로 격리된 작업 트리를 만들고 그리 옮겨 앉는다. 지금 내가
이 답을 쓰는 자리 자체가 이미 그런 워크트리(`ppanam-review-issues-4058bc`) 하나다. 즉 "자리별
작업 트리"는 새로 만들 개념이 아니라, **세션을 띄울 때(server/session.mjs spawnFor) 자리마다
다른 워크트리에서 claude 를 띄우는 것**으로 충분하다 — 새 격리 장치를 안 만들어도 된다.

## 제안 구조

1. **자리마다 전용 워크트리 + 브랜치.** `server/session.mjs` 의 `spawnFor(team, actor)` 가
   `child_process.spawn` 에 주는 `cwd` 를 지금처럼 저장소 루트(`ROOT`) 하나가 아니라
   `.claude/worktrees/<team>-<actor>/` 로 준다. 브랜치 이름도 `<team>-<actor>` 로 고정(재사용) —
   세션이 새로 떠도 같은 브랜치를 계속 쓴다(`git worktree add` 는 브랜치가 있으면 그냥 붙는다).
   총괄실 세션(system·secretary, N1) 은 예외 없이 **하나뿐인 진짜 집 워크트리** 그대로 둔다 —
   그가 보는 것은 이미 "합쳐진 뒤"의 진실이어야 한다.

2. **서버(대표 화면)는 트럭(trunk) 워크트리 하나만 읽는다.** 지금 이 저장소가 그 트럭이다 —
   `server/index.mjs` 의 `fs.readFileSync` 들이 보는 경로는 안 바뀐다. 자리 워크트리의 커밋은
   트럭에 **합쳐지기 전까지 대표 화면에 안 뜬다** — 이건 사고가 아니라 결이다: "만든 사람이
   판정하지 않는다"(R25) 원칙과 같은 문 — 검토 전 물건이 화면에 새는 게 오히려 지금 문제다.

3. **합치는 문 = 이미 있는 B 푸시 문.** `bus/approve.mjs --request B --push`(결정 63) 가 이미
   "판정 카드가 있어야 민다"를 강제한다. `server/executor.mjs` 의 푸시 실행 자리에 한 단계만
   추가: origin 에 밀기 전에 `git -C <트럭> merge --no-ff <team>-<actor 브랜치>` 를 먼저 하고,
   성공하면 그 다음이 지금과 같은 푸시. 새 승인 등급도, 새 카드 종류도 필요 없다 — 지금 있는
   "감사 통과 + 완료 조건"(D1) 문이 그대로 "합침" 의 문이 된다. 실패(충돌)하면 카드는 거부되고
   "합치는 중 충돌났습니다 — 직접 보세요" 로 떨어진다(자동으로 아무거나 골라 합치지 않는다).

4. **대표님 화면이 언제 바뀌나(세라가 조건으로 건 질문, 나리 지적으로 정정).** **지금은 즉시** —
   모두가 같은 트리를 쓰니 테라가 `app.js` 를 고치면 커밋 전이라도 새로 고침 한 번에 바로 뜬다.
   **O5 뒤엔 감사 통과 + 트럭에 합쳐진 뒤에야** 뜬다 — 판정 카드가 실제로 트럭에 merge 된 순간이지,
   자리 워크트리에 커밋한 순간이 아니다. 이건 체감이 안 바뀌는 게 아니라 **실제 지연이 새로 생기는
   것**이다 — "만든 사람이 판정하지 않는다"(R25) 문에 맞춰 대표 화면도 "감사 지난 것만" 으로
   바뀌는 셈이라 방향은 맞지만, 지금처럼 진행 중인 걸 실시간으로 보던 습관과는 다르다는 걸
   분명히 하고 넘어가야 한다.

## 열린 물음 — 나리 안(세라 검수 전, 아직 결정 아님)

- **몇 자리부터.** 테라·솔라 둘부터 — 오늘 커밋 섞임의 대부분이 이 둘이었다.
- **충돌 처리.** 그 자리(실무 본인)가 직접 푼다 — 나리는 판정만.
- **워크트리 정리.** 40분 안 불리면(D4 위임 마감 감시와 같은 창) 폴더만 지운다 — 브랜치는 남긴다.
- **회차 중간 진행 표시.** 아직 답 없음 — work.json 의 `진행` 상태는 이 변경과 무관하게 그대로
  보인다는 점만 확인됐고, 코드 diff 실시간성은 더 물어야 한다.

## 안 하는 것 (지금 범위 밖)

서버가 여러 워크트리를 동시에 읽어 화면을 그리는 것(2안)은 안 한다 — 트럭 하나만 읽는 지금
구조를 그대로 두는 1안이 기존 코드(`paths()`·모든 `fs.readFileSync`)를 하나도 안 바꾼다.
