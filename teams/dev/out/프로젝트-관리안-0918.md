# 프로젝트 관리안 — 회차 대신 작업 보드를 근원으로 (개발팀 제안 3판, 테라 2026-09-18 오후 · 솔라 둘 + 나리 둘 반영)

대표 원문(09-18 14:1x, 개발 방): "회차시스템이 그럼 설계 오류인거잖아. … 나리,세라,나래 주제로 올려서 너희가 새로운 프로젝트 관리안 가져와. 우측 상황판 개선이랑도, 대시보드랑도 구조적으로 맞물려서 돌아가야해."
비서실 셋(나리·세라·나래)의 동의 뒤 적용 — 이 장은 그 공격을 받으려고 낸 초안이다. 솔라(서버)가 3·4절을 봤다 — 구조는 맞고, 걸린 줄 둘(4절 3번 문장 좁힘·팀별 세 줄 층)을 2판에 반영했다.

## 1. 무엇이 틀렸나 (오늘 실측)

- 화면이 팀 상태를 **회차(round)** 로 읽는다: 회차가 돌면 '진행 중', 아니면 '대기'. 비서실·총괄실은 회차가 없는 방이라 세라가 하루 종일 일해도 '대기'로 찍혔다(대표 14:0x 지적, 화면 임시 고침 7637448).
- '진행 중인 사항'도 회차와 상황판(progress.json)에서 나온다. 상황판을 안 쓰는 방(비서실·총괄실)은 빈 카드다.
- 대표 화면에 회차 번호는 이미 없앴지만(결정 203), **속에서는 여전히 회차가 시계**다 — 판정·일지·세션 정리가 회차에 묶여 있고, 팀 상태·진행 표시도 거기서 나온다.
- 같은 사실을 담는 파일이 넷이다: 상황판(progress.json, 사람이 명령으로 씀) · 작업 보드(state/work.json, 톰이 관리) · 순서 목록(order.md, 팀장이 씀) · 팀별 세 줄(팀별-세줄.md, 하영이 씀). 넷이 서로 안 맞으면 화면마다 다른 말을 한다.

## 2. 원칙 셋

1. **근원 하나** — 팀이 하는 일은 전부 작업 보드(state/work.json) 한 곳에. 팀·단계·작업·담당·책임자·상태·시작·끝·앞 일(after)·결과물. 비서실·총괄실도 같은 보드에 줄을 둔다.
2. **회차는 세션 시계, 일의 시계가 아니다** — 회차는 세션이 언제 읽고 쓰고 정리하나를 정한다(일지·컨텍스트 비우기·판정 부르기). 팀 상태·진행·막힘은 회차가 아니라 **작업 상태와 사람 상태**에서 계산한다.
3. **화면은 계산하지 않고 읽는다** — 왼쪽 팀 줄·우측 상황판·대시보드·타임라인 넷이 같은 서버 자료 하나를 읽는다. 화면마다 따로 세지 않는다.

## 3. 구조 — 자료 하나, 화면 넷

| 자리 | 지금 읽는 것 | 바꾼 뒤 읽는 것 |
| --- | --- | --- |
| 팀 상태(진행 중·대기·막힘) | 회차 phase | 그 팀 보드에 '진행' 작업이 있으면 진행 중, '막힘'이 있으면 막힘, 사람이 일하고 있으면 진행 중, 아니면 대기 |
| 왼쪽 팀 줄 한 줄 | 팀별 세 줄 → 상황판 doing | 보드의 '진행' 작업 첫 줄 + 누가 |
| 우측 상황판(팀 카드) | progress.json 다섯 칸 | 진행 중 = 보드 '진행' · 다음 = 시작할 수 있는 작업(after 풀림) · 예정 = 그 뒤 · 막힘 = 보드 '막힘' + 병목 사람 · 정할 것 = 결재 C·물어봄 |
| 대시보드 팀 다섯 | /api/card(상황판) | 같은 카드, 같은 자료 — 비서실도 카드 하나 |
| 타임라인 | /api/timeline(보드 + 회차 주 묶기) | 그대로 — 이미 보드가 근원 |
| 순서 목록 order.md | 팀장이 손으로 씀 | 보드에서 도구가 뽑는 표(work-board.mjs --team, 톰 229) — 손으로 쓰는 건 팀 목표 한 줄뿐 |
| 팀별 세 줄 md | 하영이 손으로 씀 | 없앤다 — 카드가 보드에서 읽는다. 단, 팀장이 문장을 확인하던 층이 같이 사라진다(솔라 2판 우려) — 보드 글이 날것으로 나가지 않게 작업 이름을 올릴 때 하영 자(사전 0절)를 지나게 하거나, 비서실 셋이 다른 길을 정한다 |

- 상황판 명령(progress.mjs --doing/--blocked/--boss)은 보드 명령으로 바꾼다: `work-board.mjs --start <작업>`·`--block <작업> "왜"`·`--done <작업>`. 사람이 '하는 것' 문장을 새로 짓지 않고 보드 작업을 고른다 — 자에 걸리는 문장이 안 생긴다.
- 자에 걸린 줄은 카드에서 빼지 않고 **"숨김 N줄"** 로 보인다(나리 3판) — 대표가 "없다"와 "안 보이게 했다"를 가를 수 있게. 누르면 원문.
- 결재·판정은 작업에 붙는다: 카드가 통과하면 그 작업이 '완료'(doneAt), 반려면 '막힘'. 회차 닫힘은 작업을 바꾸지 않는다 — 세션만 정리한다.
- 회차는 남긴다: 세션 컨텍스트 비우기·일지·판정 부르기·rounds.jsonl 주 묶기. 대표 화면엔 안 보인다(203 그대로).

## 4. 순서 — 누가 무엇을 (담당만)

1. **비서실 셋** — 이 장 공격·동의(대표 지시 셋의 루프). 3절 표에서 틀린 줄을 짚는다.
2. **톰** — 비서실·총괄실 작업이 보드에 없는 줄을 채운다(톰 3판: 지금 총괄실 열넷·비서실 다섯 줄이 이미 있다 — "0줄"은 제가 안 세고 쓴 틀린 말), 순서 목록을 도구로 뽑는 것으로 바꾼다(229 솔라 줄과 같이).
2-1. **솔라(보드 칸 먼저, J24)** — 작업마다 시작·끝·결과물 칸(startedAt·doneAt·outputs)이 서버가 찍히게 — 팀 상태 계산(3번)보다 앞(나리 3판: 칸이 없으면 상태를 셀 재료가 없다).
3. **솔라(서버)** — 팀 상태 계산을 회차 phase 대신 보드·사람에서(`teamSummary.state`) · /api/card 다섯 칸을 보드에서 · 보드 명령 셋(--start/--block/--done) · 회차 phase 를 **화면의 진행/대기 판정에서만** 뺀다(솔라 확인 2판: 판정 통과 → 작업 완료 길 `advanceWorkOnPass` 는 그대로 — 끊으면 통과해도 작업이 영영 '진행'에 남는다). 계약 3·4절 고침.
4. **테라(화면)** — 왼쪽 팀 줄·우측 상황판·대시보드 팀 다섯·비서실 카드가 새 자료를 읽게. 임시 고침 7637448 은 그때 지운다.
5. **헨리** — 우측 상황판 새 시안(대표 "우측 상황판 개선"): 팀 카드와 같은 부품으로, 폰·PC.
6. **하영** — 상태 낱말(진행 중·대기·막힘·시작할 수 있음·완료)은 사전 111~125행 그대로, 새 낱말 0.
7. **레오·마크** — 판정. 나래 사진, 세라 30초.

## 5. 통과 조건

- 비서실·총괄실이 왼쪽 줄·카드·대시보드에서 다섯 팀과 같은 모양으로 선다(회차 없이).
- 같은 팀의 '진행 중' 줄이 왼쪽 팀 줄·우측 상황판·대시보드·타임라인 넷에서 글자까지 같다(사진 넷).
- 상황판 파일(progress.json)을 아무도 안 써도 화면이 빈 데 없다.
- 회차 번호·회차 상태를 대표 화면에서 읽는 코드 0(자로 확인).
- 노라 30초 — 처음 보는 눈으로 비서실 카드·왼쪽 줄을 30초 안에 읽고 "누가 무엇을 하는 중인지" 말할 수 있다(나리 3판).
