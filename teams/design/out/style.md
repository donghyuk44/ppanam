# 우리 마을 도트 양식서

2026-09-12 · 디자인팀 M1 · 쓴 사람 헨리. 이 문서가 먼저고 그림은 그 다음이다.
여기 어긋난 그림은 예뻐도 버린다. 숫자는 전부 `tools/pixel/check.mjs` 가 재는 값과 같다.

> 2026-09-12 대표 결정 — 캐릭터 키는 **64 px** 다. 로드맵 M1 에 적힌 32×48 로 열 장을 뽑아 나란히 보니 얼굴·옷이 뭉개져서, 64px 시트와 비교한 뒤 64 로 바꿨다. 32×48 로 만든 열 장은 버린다. 정지 그림은 ChatGPT, 걷기는 PixelLab 에 그 정지 그림을 참고로 넣어 뽑는다. 칸 크기는 도구마다 달라서 고정하지 않고 **발 가운데 앵커**로 맞춘다(3절).

## 1. 시점과 등신

- **시점** — 살짝 내려다보는 3/4 탑다운. 지붕 윗면이 보이고 벽 앞면도 보인다. 캐릭터는 정면(남)에서 얼굴 전체, 옆(동·서)에서 코 윤곽, 뒤(북)에서 머리 뒤통수.
- **등신** — 3~3.5등신. 머리(머리카락 포함)가 몸통보다 크거나 같다. 머리카락에 부피를 준다. 바람의나라: 연·도깨비의세계의 비율을 참고하되 그림은 새로 그린다.
- **참고** — 남의 게임 그림은 `teams/design/ref/`(저장소 밖)에 두고 생성 도구의 참고 입력으로만 쓴다. 구도·시점·비율·색감까지가 참고고, 결과물이 그걸 베끼면 버린다.

## 2. 격자 — 숫자

| 것 | 값 |
| --- | --- |
| 타일 | 32×32 px |
| 캐릭터 키 | **약 64 px** (머리 꼭대기~발바닥, 타일 두 칸). 갓·상투 포함 58~64. 열다섯 실측 59~62 |
| 캐릭터 칸 | **고정하지 않는다.** 정지 그림은 칸 = 그림 크기(여백 자름), PixelLab 시트는 도구가 주는 칸(대표 시험본 88×88, 그림 40×64 가 칸 가운데). 칸 대신 **앵커**(아래 3절)로 맞춘다 |

## 3. 앵커 — 모든 칸이 같은 자리에 선다

칸 크기가 그림마다 달라도 **발 가운데 한 점**이 앵커다. 마을 탭은 캐릭터를 이 점으로 타일에 세운다.

- **앵커 `[centerX, footline]`** — 시트마다 하나. `footline` 은 접지한 발의 가장 아래 불투명 픽셀이 있는 줄, `centerX` 는 몸통 실루엣(소매·발끝·갓 챙 말고 몸통)의 가로 중간. 시트 안 모든 칸이 같은 값이다. **마을 탭 앵커의 y 는 `footline + 1`** — 픽셀 줄이 아니라 그 아래 모서리(땅)다.
  - 정지 그림(칸 = 그림 크기): `footline = 높이 − 1`, `centerX = 몸통 기준점`(아래 `torsoX`).
  - PixelLab 시트(칸 88×88): **`footline = 74`, `centerX = 44`, 마을 앵커 `[44, 75]`.** 대표 시험본 40칸 실측(`out/feet/boss-walk.json`)으로 확정 — 발 밑선이 한 픽셀도 안 흔들린다. 가로 x=25~62 의 중간 43.5 를 올려 44.
- 걷는 동안 **머리와 몸은 위아래로 2px 까지 흔들려도 되지만 발 밑선은 안 움직인다.** 든 발은 밑선보다 위에 있어도 된다.
- 칸 가장자리는 1px 이상 비운다 (`check.mjs --cell` 이 가장자리 픽셀을 침범으로 잡는다). 갓·모자·소매를 다 포함한 폭이 칸을 넘지 않는다.

### 발 상자 메타데이터 (`out/manifest.json`)

시트 하나에 `anchor` 하나, 칸마다 `frames[]` 항목 하나. 좌표는 **칸 안 기준**이고 `left`/`right` 는 **화면 기준**(보는 사람의 왼쪽)이다. 캐릭터 기준으로 적으면 남향과 북향에서 뒤집혀 스크립트가 반대 발을 잰다.

```json
{
  "cell": [88, 88],
  "anchor": { "footline": 74, "centerX": 44 },
  "frames": [
    { "dir": "rot",   "pose": "0", "planted": "none", "feet": { "left": [31, 69, 13, 6], "right": [44, 69, 13, 6] } },
    { "dir": "south", "pose": "0", "planted": "both", "feet": { "left": [32, 69, 11, 6], "right": [43, 69, 11, 6] } },
    { "dir": "south", "pose": "1", "planted": "left", "feet": { "left": [32, 69, 11, 6], "right": [43, 66, 11, 6] } }
  ]
}
```

- `feet.left`·`feet.right` = `[x, y, w, h]` 두 발의 상자. 시트의 모든 칸에 둘 다 적는다 (그림자·옷자락 오인 방지). PixelLab 시트는 0줄 여덟 칸이 `dir: "rot"`(8방향 정지, `planted: "none"` — 앵커만 잰다), 걷기는 방향당 8프레임이라 `pose` 는 `"0"`~`"7"`, `planted` 는 프레임을 보고 정한다. `tools/pixel/feet.mjs` 가 이 형식으로 잰다.
- `planted` = 그 칸에서 밑선에 닿아 있어야 하는 상자. `both` 면 두 상자 다 `footline` 에 닿는다. `left`/`right` 면 그 상자만 잰다.
- 옆모습 예시 — **서향 "왼발 앞" 칸**은 앞으로 나간 발이 화면 왼쪽이라 `planted: "left"`. **동향 같은 자세**는 앞발이 화면 오른쪽이라 `planted: "right"`. 옆모습에서 두 발 상자가 겹쳐도 상자 안의 최하단 픽셀만 재므로 괜찮다.
- 위 값은 형식 예시다. 실제 좌표는 시트가 나온 뒤 픽셀을 보고 적는다.

### 몸통 기준점 `torsoX` — 가로 흐름 잡기

도구가 뽑은 시트는 칸마다 그림이 1px 씩 옆으로 밀려 나올 수 있다 (32×48 시험본 boss·hq-chief 에서 실측: 남향 줄이 칸마다 1px 씩 왼쪽으로). 발 상자나 전체 상자의 중간은 소품·팔·발에 끌리므로 쓰지 않는다.

- **산출 구간** — 발 밑선에서 위로 잰다: `y = footline − 18 .. footline − 8` (양 끝 포함, 열한 줄), 도포 자락 띠. 소매·부채·화첩·발이 안 걸리는 줄이다. 64 높이 정지 그림이면 44..54, PixelLab 88 칸(footline 74)이면 56..66. (대표 정지 그림 실측: 부채 든 손 y≈29~37, 자락 40~56, 신 58~62.) **임시값** — 걷기 프레임에서 든 발이나 흔들리는 자락이 이 띠에 들어오는지 마크가 대표 시험본 40칸에서 실측한 뒤 확정한다.
- **계산식** — 그 열한 줄에서 불투명(알파 255) 픽셀의 가장 왼쪽 `minX` 와 가장 오른쪽 `maxX` 를 잡고 `torsoX = round((minX + maxX) / 2)`. 반올림은 0.5 를 올린다.
- **보정** — `shift = centerX − torsoX`. 칸 전체를 가로로 `shift` 만큼 옮긴다. 옮긴 뒤 픽셀이 칸 가장자리 여백을 침범하면 자르지 않고 실패로 기록한다 (그림이 너무 넓은 것이다). 정지 그림(칸 = 그림)은 옮길 게 없다 — `torsoX` 자체가 `centerX` 가 된다.
- **기록** — manifest 프레임마다 `torsoX: { before, shift, after }` 를 적는다. `after` 는 시트 안 모든 칸이 `centerX` 여야 한다. 발 밑선은 가로 이동으로 안 바뀌므로 보정 뒤에도 `footline` 그대로다.
- 이 구간·계산식은 `fix.mjs --centerx` 와 `check.mjs --torsox` 가 같은 것을 쓴다. 바꾸면 여기와 두 스크립트를 같이 바꾼다.

## 4. 선과 빛

- **외곽선** — 1px, 팔레트의 `#1b1a1f`. 실루엣 바깥은 전부 두른다. 안쪽 선은 같은 색이 맞닿아 구분이 안 될 때만 (소매와 몸통, 앞섶).
- **빛** — 왼쪽 위(북서)에서 온다. 밝은 면은 왼쪽·위, 그늘은 오른쪽·아래. 열다섯 명, 모든 타일이 같다.
- **명암** — 옷 색은 팔레트에 한 색뿐이다. 그늘은 `#3d3a44` 나 외곽선과의 디더, 밝은 면은 `#f4efe4`/`#d9d1bf` 와의 디더로 낸다. 중간색을 새로 만들지 않는다.
- **그림자** — 캐릭터 밑 드롭섀도 없음. 필요하면 마을 탭이 타일 위에 그린다.
- **눈** — 두 눈이 각각 보인다. 안경은 64px 에서도 눈과 뭉개져 감은 눈처럼 보인다(헨리 1차에서 확인) — 쓰지 않는다.

## 7. 도구와 이유

**정지 그림은 ChatGPT, 걷기는 PixelLab, 정리와 검사는 `tools/pixel/fix.mjs` → `check.mjs`.**

- **정지 그림 (얼굴·옷의 기준)** — ChatGPT 이미지 생성. 대표가 이미 가진 도구고, 참고 그림 셋(`ref/baram/char_magician.png` · `ref/baram/char_thief.png` · `ref/dokkaebi/i1540213767.jpg`)과 게임 링크를 같이 넣을 수 있다. 대표 캐릭터 첫 실물(2026-09-12)이 이 길로 나왔고, 열다섯 장 전부 이 길로 나왔다(`out/sprites64/`, 17~27색). 프롬프트는 `out/gpt/requests/<이름>.json` — 인물 묘사는 6절 표 그대로고 끝 절만 정지 낱장 규격이다.
- **걷기 시트** — PixelLab. 정지 그림을 참고로 넣으면 8방향 정지 1회 + 방향별 걷기 8프레임 1회씩. 한 명 = 정지 1 + 걷기 4(남·동·북·서) = **5회**. 무료 40회면 여덟 명. 대표 시험본(`out/gpt64/boss-pixellab-sheet.png`, 20색)이 통과하면 나머지 일곱은 월 12달러 요금제 — 대표 판단(C). 나쁘면 걷기는 ChatGPT 64×64 칸 시트(대표 첫 시트 규격, 2048×2048)로 간다.
- **32×48 은 왜 버렸나** — 열 장을 뽑아 나란히 세워 보니 얼굴이 뭉개지고 옷 무늬가 사라졌다. 64px 시트와 비교한 뒤 대표가 64 로 정했다. `out/sprites/` 의 32×48 결과와 `out/feet/` 실측은 그 시험의 기록으로만 남긴다.
- `fix.mjs <in> <out> --grid 64 --key ff00ff --palette out/palette.json --despeckle 60 --trim` — 정지 그림: 임의 배율 원본(512 든 ChatGPT '저장'의 1254 든)을 64 격자로 샘플, 자홍 투명, 팔레트 스냅, 떨어진 조각 제거, 여백 자름. `--sample mode` 로 블록 안 최빈색을 고른다.
- `fix.mjs <in> <out> --palette out/palette.json` — PixelLab 시트: 배경이 이미 투명이라 키 제거는 없고 팔레트 스냅만. 대표 시험본은 발 밑선·중심축이 40칸 다 같아서 `--footline`·`--centerx` 보정이 필요 없었다 — 다음 사람에서 흐르면 `--cell 88x88 --footline 74 --centerx 44` 로 잡는다. **시트엔 `--trim` 을 쓰지 않는다** — 칸이 그대로 남아야 앵커를 잰다.
- `check.mjs <파일> --palette out/palette.json [--cell WxH --torsox]` — 크기·칸 가장자리·팔레트·반투명·모서리·중심축. 마크가 같은 명령으로 판정한다. 발 상자는 `feet.mjs` 로 재서 manifest 에 옮긴다.
- 유료 픽셀 도구(SpriteCook 플러그인은 설치돼 있고 OAuth 대기)는 PixelLab 으로도 걷기가 안 풀릴 때 검토한다.
