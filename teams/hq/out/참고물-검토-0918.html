참고물 검토 — 대표가 보낸 셋 (2026-09-18, 나래)

대표 원문(10:4x): "아래 것도 검토 바람, 마인드맵 또는 지식그래프인데 누군가의 오픈소스임(GitNexus)" · "클로드 코드 내에 knowledge graph를 만드는 Artifacts가 있고 … 어디에서 새로 어떻게 만드는지 방법을 못찾겠어서 인터넷 검색으로 찾는걸 명령함" · "내가 원하는 업무 관리방식은 지금 두 링크 보낸것과 비슷하게(레딧·티스토리)".

꼴은 규칙대로 — 배운 것 → 우리에 맞춘 것 → 여쭙는 것. 링크마다 인용 한 줄. 세라 검수 뒤 대표께. 안 본 것은 끝에.

1. 대표가 원하는 업무 관리 방식 — 링크 둘 (Synapse · Agent Flow)

배운 것

  • 레딧 글 = Synapse(Soarcer, 2026-03, MIT, npm @synapse-ai/cli 0.1.3, 깃허브 별 16). 대표가 PDF 로 뽑아 준 원문에서 — "Claude Code가 에이전트를 생성하고, 도구를 호출하고 … 전체 세션을 실시간으로 상호 작용하는 노드 그래프로 렌더링합니다." 보여 주는 것: 에이전트 생성·도구 호출·하위 에이전트를 연결된 노드로 · 노드 검사기("이 도구가 정확히 뭘 했지?") · 도구 호출 묶기(알약 격자·타임라인·빈도 표) · 렌즈 넷(트리맵·Sankey·압축 타임라인·트리) · 폰에서 전체 대시보드 + 승인 · 설치 한 줄(npm install -g @synapse-ai/cli → synapse start). 원리(작성자 댓글): "Claude Code 훅은 모든 도구 호출, 에이전트 생성, 세션 수명 주기 이벤트에 대해 이벤트를 발생시켜요 … HTTP를 통해 실시간으로 로컬 서버에 POST … 토큰 수나 모델 정보처럼 훅이 노출하지 않는 데이터를 위해 JSONL 트랜스크립트 파일을 감시해요." 한계(작성자): 하위 에이전트에 무슨 맥락이 들어갔는지는 못 본다(훅이 안 줌).
  • 티스토리 글 = Agent Flow(patoles, Apache-2.0, 깃허브 별 1,648, VS Code 확장도 있음). 글에서 — "Claude Code 에이전트 오케스트레이션을 실시간 인터랙티브 노드 그래프로 시각화" · 화면 셋: 노드 그래프(색으로 상태 — 실행 중·완료·오류) · 타임라인 패널("수평 간트 차트 형태 … 어떤 Tool Call이 병목인지 즉시 파악") · 트랜스크립트 패널(노드 클릭 → 그 시점 기록으로) · 다중 세션 탭(워크스페이스의 Claude Code 세션을 자동으로 찾아 탭으로). 깃허브 README — "Claude Code + Codex: Auto-detects sessions from both runtimes" · 사용법 npx agent-flow-app(훅을 ~/.claude/settings.json 에 등록, 기본 포트 3001) · ~/.claude/projects/ 의 세션 파일도 읽음.
  • 둘의 공통 = 훅 사건(도구 호출·에이전트 생성) + 세션 기록(토큰) → 그래프·타임라인·기록 세 화면. 대표 원문 "에이전트들이 어떤 순서로 일을 하는지 · 어디가 왜 느렸는지 · 딴짓하지 않는지 · 지금 무얼 처리하고 있는지" 넷을 화면 하나로 답하는 꼴이다.

우리에 맞춘 것

  • 우리는 같은 재료를 이미 갖고 있다. 훅(.claude/hooks/to-bus.mjs)이 자리마다 도구 사건(Read·Edit·Bash·Write, 경로까지)을 teams/<팀>/log.jsonl 에 남기고, 토큰은 state/usage.jsonl(자리·회차·세션), 회차 길이는 rounds.jsonl, 결재 단추는 이미 폰에서 된다. 없는 것은 그 재료를 그래프·간트·기록으로 그리는 화면 하나다(09-16 실측: 화면은 셀 수 있는 것을 안 세고 있었다).
  • 그래서 둘을 베끼지 않고 대시보드 첫 판(대표 답 "사람·막힘·반복 읽기")을 이 세 화면 꼴로 만든다: ① 사람마다 노드(살아 있음·지금 도구·지금 카드) ② 카드마다 간트 막대(시작→끝, 막힌 구간 빨강) ③ 노드를 누르면 그 자리의 기록(무엇을 읽었나·몇 번 읽었나). 낱말은 사전에 있는 것만(타임라인·간트·기록). 헨리 시안 → 테라 → 안젤 → 마크 → 나리 판정 순서 그대로(계획 8단계).
  • 재료 둘은 지금 없어 먼저 적어야 한다(계획 5·7단계): Read 사건에 offset(부분 읽기 구분), 사건에 카드 id.
  • 먼저 눈으로 보는 길: Agent Flow 는 ~/.claude/projects/ 의 세션 기록을 자동으로 읽으니, 우리 자리 열다섯(서버가 띄운 claude 세션)도 그대로 탭으로 뜬다 — 코드 한 줄 없이 "대표가 원하는 화면이 이것인가"를 10분 안에 확인할 수 있다. 단 npx agent-flow-app 은 ~/.claude/settings.json 에 훅을 등록한다(대표 컴퓨터 설정) — 설치는 대표 허락 뒤.
  • Synapse 의 "폰에서 승인"은 우리 결재 단추와 같은 일이라 안 가져온다(한 물건 두 길 금지).

여쭙는 것

  • Agent Flow 를 지금 제 손으로 띄워 대표님이 폰·PC 로 10분 보시겠습니까? (설정 파일에 훅 한 줄이 들어갑니다. 안 맞으면 바로 지웁니다.)

2. GitNexus — 코드 지식 그래프

배운 것

  • 깃허브 README — "Indexes any codebase into a knowledge graph — every dependency, call chain, cluster, and execution flow — then exposes it through smart MCP tools so AI agents never miss code." 핵심은 "Precomputed Relational Intelligence": 색인할 때 미리 구조를 계산해 두어 "no 10-query chains to understand one function", 작은 모델도 전체 구조를 본다. 설치 npx gitnexus analyze → npx gitnexus setup(MCP 등록). 웹 UI(gitnexus.vercel.app, 브라우저 안에서만 돎), 위키 생성(LLM 필요), 지원 언어에 JavaScript·TypeScript 있음. 별 47,408(2026-09-17 실측). 라이선스 PolyForm Noncommercial — README 1039행 "Commercial use of the OSS version is also available with proper licensing."
  • 주의: analyze 가 "installs agent skills, registers Claude Code hooks, and creates AGENTS.md / CLAUDE.md context files" — 우리 CLAUDE.md(60줄 규칙)와 .claude/ 를 건드린다.

우리에 맞춘 것

  • 대표가 부른 이름은 "마인드맵·지식그래프"인데, 실물은 코드 구조 색인 + 에이전트용 MCP 도구다. 우리 문제 중 정확히 맞는 자리는 하나 — 반복 읽기. 09-16 실측: 솔라가 한 회차에 bus/bus.mjs 를 49번, 하루에 bus/round.mjs 72번 읽었다. GitNexus 의 impact/context 도구는 "이 함수를 누가 부르나"에 한 번에 답하니, 큰 파일을 다시 읽는 대신 도구 한 번으로 끝난다.
  • 그러나 상업 이용이 막힌 라이선스라 회사 도구로 정식 채택은 못 한다(유료 라이선스는 대표 결정 = 돈). 같은 자리를 우리 것으로 메우는 길: 책장(shelf.md)의 "전문 Read 금지 — 함수 이름으로 grep" 규칙을 세션에 넣고(계획 5단계), 색인 tools/library.mjs 에 코드까지 넣는 것(지금은 md·txt·json 만).
  • 시험은 저장소 복사본에서만(CLAUDE.md·.claude 를 건드리므로), 결과는 "테라·솔라의 한 회차 Read 수가 줄었나"로 잰다.

여쭙는 것

  • GitNexus 는 (ㄱ) 복사본에서 한 번 시험해 반복 읽기가 줄어드는지 잰다 / (ㄴ) 라이선스 때문에 보류 — 어느 쪽입니까? (저는 ㄴ 보류를 권합니다 — 반복 읽기는 먼저 규칙과 우리 색인으로 줄이고, 안 줄면 그때.)

3. 클로드 코드 안에서 지식 그래프 만드는 법 — 찾았다

배운 것

  • 대표가 8월 8일에 본 것은 데스크톱 클로드 코드의 /understand 스킬(Understand Anything)이다. 스킬 원문 — "Analyze a codebase to produce an interactive knowledge graph for understanding architecture, components, and relationships" · 산출물은 저장소의 .ua/knowledge-graph.json(옛 이름 .understand-anything/) · 보는 법은 /understand-dashboard("Launch the interactive web dashboard to visualize a codebase's knowledge graph") · 묻는 법 /understand-chat · 한국어 --language ko · 큰 폴더 빼기 --exclude "…".
  • 8월 샘플이 없어진 이유(추정, 스킬 원문 근거): "Worktrees managed by Claude Code are ephemeral — the data directory (.ua/) written there is destroyed when the session ends, taking the knowledge graph with it (issue #133)." 지금 버전은 작업 트리에서 실행해도 본가지 폴더에 쓴다. tritrip·triptude·ppanam 셋 다 .ua/·knowledge-graph.json 이 없다(실측).
  • 만드는 자리: 데스크톱 클로드 코드(이 창처럼 anthropic-skills 가 보이는 세션)에서 /understand --language ko 한 줄. 팀원 세션(서버가 띄우는 claude)에는 이 스킬이 없다.
  • 비용: 파일을 묶음으로 LLM 이 읽어 요약한다 — ppanam 크기에서 얼마인지는 안 실행해 봐서 모른다(안 봄).

우리에 맞춘 것

  • 이것은 "코드가 어떻게 생겼나"의 그래프이지 "팀이 무엇을 하고 있나"의 그래프가 아니다 — 대표 대시보드(1절)와 다른 물건. 쓸 자리는 헌법 4절 색인의 부록(개발팀 온보딩·레오 감사가 코드 구조를 볼 때)이다.
  • 실행하려면 본가지 폴더(~/Documents/ppanam)가 최신이어야 한다 — 지금 그 폴더는 09-16 실측대로 535 커밋 뒤(bf81ead)라 먼저 git merge --ff-only 로 맞춘다(관리 창 일).

여쭙는 것

  • 본가지 최신화 뒤 /understand --language ko 를 한 번 실행해 결과 화면을 보여 드릴까요? (토큰이 들고, 얼마인지는 실행해 봐야 압니다.)

안 본 것

  • 레딧 본문은 대표 PDF 로 읽었고 댓글 12개 중 뒤 몇 개는 잘림. Synapse 깃허브 README 는 404(기본 가지 이름 다름) — npm 설명·홈페이지로 대신 봄. Agent Flow·GitNexus·Synapse 를 실제로 실행해 보지는 않음. /understand 의 ppanam 비용 미측정. GitNexus 라이선스 전문(PolyForm Noncommercial 1.0.0)은 이름만 확인, 조문은 안 읽음.
