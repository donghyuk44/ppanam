## 공격 1 — 정본 명령이 매우·긴급을 맨 위에 놓지 않는다
2판의 jq 줄을 `state/work.json`(107건)에 실행하면 첫 여섯 줄이 **칸 없는 항목**(J27·J28·J29·J30·J16·J17)이다 — jq 는 빈 칸(null)을 글자보다 앞에 놓는다. 또 지금 정렬은 "매우 < 보통 < 아님", "긴급 < 보통 < 여유"가 **글자 순서로 우연히** 맞는 것이라, 낱말 하나만 바뀌어도 순서가 무너진다.
고친 줄(등급표로 정렬 · 칸 없음은 맨 뒤 · 기다리는 수는 `after` 칸을 거꾸로 세서 지금 바로 나옴 · 같은 칸 안은 기다리는 수 → 번호):

```
jq -r '.items as $all
| [ .items[] | select(.status!="통과" and .status!="안 함") | .id as $id
    | . + { rank: ((({"매우":0,"보통":1,"아님":2}[.importance // "?"]) // 9)*10 + (({"긴급":0,"보통":1,"여유":2}[.urgency // "?"]) // 9)),
            waiters: ([ $all[] | select(.status!="통과" and .status!="안 함") | select((.after // []) | index($id)) ] | length) } ]
| sort_by(.rank, -.waiters, .id) | .[]
| "\(.importance // "칸없음")/\(.urgency // "칸없음") 기다림\(.waiters) \(.team) \(.status) \(.owner) \(.id) \(.what[0:28])"' state/work.json
```

## 공격 2 — 감사 대기 열셋을 다 솔라 줄에 놓으면 무더기가 자리만 옮긴다
결과물 파일이 장에 적힌 것은 다섯(D1·D3·T2·T4·C5)뿐이다. 나머지 여덟(T3·C6·C7·O1·K1·K3·K4·J1)은 판정할 물건이 안 적혀 있다 — D1 의 규칙("결과물 파일이 있어야 끝내라고 부른다")대로 그 여덟은 짝 줄이 아니라 **테라 줄 "결과물 채우기"**(톰 J31 줄 그대로)다. 솔라 '지금' 후보는 다섯.

## 공격 3 — 보드의 '진행'이 사람마다 하나가 아니다
