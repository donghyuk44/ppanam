# 그래프 보기 — 우리만의 것 제안 (2026-09-18 11:1x, 나래)

대표 원문(11:0x): "내가 준 지식그래프와 GitNexus, 레딧 게시물의 프로그램, 블로그 게시물은 우리가 그걸 참고분석해서 우리만을 위한 똑같은것을 만들어내라는 말이야. 이미 소스가 다 있잖아. 켜보고 너가 테스트 해보면서 웹서치로 키워드를 넣었을 때 나오는 다른 비슷한 프로그램이나 서비스 대비 좋은지 체크 후 적용하면 됨." · "(GitNexus, Agent Flow, knowledge graph) 예시를 보면 하나의 공통된 내 요구사항이 보이지 않니?"
꼴: 공통 요구 → 실제로 켜 본 것 → 비슷한 것 비교 → 우리 것 설계 → 순서·담당 → 여쭙는 것. 세라 검수 뒤 개발·디자인 순서 목록으로.

## 1. 공통 요구 — 대표 원문(11:1x)이 정본

> "업무 관리를 마치 마인드맵처럼, 지식그래프처럼, 바둑판 위의 바둑돌처럼 유기적으로 연결되서 어디가 꼬인게 없는지, 전체적으로 작업들이 어떻게 연결되어있는지 보고싶다!"

풀어 쓰면: **일(작업)이 점, 일 사이 관계가 선인 한 화면.** 사람 열일곱(팀원 열다섯·나리·나래)·문서(산출물)·코드는 그 일에 붙는 점이다. 선 = "무엇이 무엇 뒤에 오나·누가 맡았나·누가 무엇을 읽고 고쳤나·무슨 결과물이 나왔나". 색 = 지금 상태(살아 있음·일하는 중·**막힘(꼬임)**·끝). 점을 누르면 상세. 시각을 뒤로 옮기면 어제가 보인다. "어디가 꼬였나"가 첫째 물음이라 **막힘 선과 빨간 점이 첫 판의 중심**이다.
- GitNexus·`/understand` = **코드·문서의 관계** 그래프(멈춰 있는 지식).
- Agent Flow·Synapse = **에이전트 행동의 실시간** 그래프(움직이는 활동).
- 대표가 대시보드에서 보고 싶다고 한 여덟(순서·소요·토큰·살아 있음·담당과 막힘·여러 일·스레드·결과물)은 전부 이 지도의 선 하나 또는 점의 색 하나다. 넷을 합친 것이 대표 요구다 — 둘 중 하나만 만들면 반쪽이다.

## 2. 실제로 켜 본 것 (11:06~)

- **Agent Flow** — `npx agent-flow-app --no-open --port 3001` 을 살아 있는 트리에서 실행. 대표 컴퓨터 설정(`~/.claude/settings.json`)에 훅 여섯 줄이 자동으로 들어갔고(`~/.claude/agent-flow/hook.js`, 2초 제한) — 시험 뒤 원래대로 되돌린다 — 파일을 다시 복사(백업 있음). 결과: 우리 자리 세션 열하나가 탭으로 바로 떴다(훅이 전역이라 자리 세션 전부 잡힘). 화면 = 세션마다 큰 점 하나(토큰 게이지 59k/1000k) + 말풍선 + 아래 실행 타임라인(Starting·Thinking·Tool call 막대) + 파일·대화·비용·타임라인 패널. 좋은 점: 설치 한 줄, 즉시. 모자란 점: 탭 이름이 우리 자리 이름이 아니라 첫 프롬프트 글자("⟦들려주기 — 기록하지..")고, 팀·회차·카드·담당·막힘 같은 우리 개념이 없다 — 세션 단위 도구 흐름만. 127.0.0.1 에만 열려 폰에서는 못 본다.
- **Synapse** — 실행 안 함(같은 원리 = 훅 + 세션 기록). 대표 PDF·홈페이지에서 본 다른 점: 렌즈 넷(트리·트리맵·Sankey·줄인 타임라인 — 원문 "압축 타임라인"), 폰 반응형, 폰에서 승인. MIT.
- **GitNexus·`/understand`** — 실행 안 함(이 글 뒤 복사본에서 시험). 둘 다 코드 관계를 미리 계산해 두는 쪽이라 실시간 화면이 아니라 "사서" 자리에 맞는다.

### 화면 셋(Agent Flow·Synapse 에서 빌린 모양) + 폰
1. **그래프** — 힘 배치(d3-force 또는 cytoscape, CDN, 개발이 고름), 팀별 묶음, 점 색 = 상태(살아 있음·일하는 중·막힘·끝·꺼짐), 점 크기 = 오늘 토큰, 선 굵기 = 횟수. 누르면 오른쪽 상세(검사기): 사람이면 지금 카드·마지막 도구·오늘 읽은 파일 상위·토큰, 일이면 담당·시작→지금·막힌 이유·결과물, 파일이면 누가 몇 번 읽고 고쳤나.
2. **타임라인(간트)** — 회차·카드 막대(시작→끝, 막힌 구간 빨강), 사람별 줄. 이미 있는 `/api/timeline` 위에 막대만.
3. **기록** — 점을 누르면 그 자리·그 시각의 방 기록으로 이동(우리 채팅이 곧 기록).
4. 폰(412) — 그래프는 팀 하나씩 확대, 기본은 사람 목록(카카오톡 친구 목록 꼴: 이름·상태 색·지금 한 줄), 누르면 상세. 펼친 폴드(750)·PC(1280)는 그래프가 기본.

### 첫 판에 넣을 것 = 대표 답 "사람·막힘·반복 읽기"
- 사람 점 색(살아 있음·지금 무엇) · 일 점 빨간 테두리(막힘)와 그 선 · 사람→파일 선 굵기(반복 읽기). 나머지 선은 자료가 생기는 대로(6·7단계).

### 재료 중 새로 적어야 하는 것(계획 5·6·7단계와 같음)
tool 사건에 `offset/limit`·세션 id · work.json `startedAt/doneAt/outputs/owner` · 사건에 카드 id · 그래프 파일 `state/graph.json`(밤마다 색인 + 낮엔 사건으로 덧씀, 솔라).

## 5. 순서·담당 (계획 7·8단계 자리 그대로 — 3~6단계(기다리는 말씀·헌법·세션 규칙·책임자) 뒤. 앞으로 당기는 것은 대표 결정, 6절)
1. 하영 — 낱말: "그래프 보기·점·선·상세" 가 사전에 서는지(옵시디언·로그시크·피그마 근거) → 한 줄.
2. 유진 — 지표 정의: 점 색·선 굵기가 무엇을 세는지(살아 있음·막힘·반복 읽기)를 경영 아침 한 장의 잣대와 같은 말로 한 장. 같지 않으면 아침 한 장을 따른다.
3. 솔라 — `state/graph.json` 첫 판(사람·일·문서·파일 점 + 맡음·뒤에 옴·읽음 선, 훅 사건으로 실시간 갱신) + `/api/graph`. 증거: json 실물, 점·선 수.
4. 헨리 — 그래프·타임라인·기록 세 화면 시안(412·750·1280), Agent Flow·Synapse 사진 참고(베끼지 않음). 마크 통과.
5. 테라 — 화면(그래프 라이브러리는 CDN, 우리 앱은 React 없음) + 상세 패널.
6. 안젤 사용성 → 노라 12살 30초 읽기 시험 → 레오(코드) → 나리 판정 → 나래 사진 셋 → 세라 대표께.
7. 그 뒤 — 코드 점을 함수 단위로(GitNexus 방식, 복사본 시험 뒤), 문서 점에 `/understand` 요약 붙이기, 스레드 선(9단계).

## 6. 여쭙는 것
- 이 설계를 개발·디자인 순서 목록에 넣되, **자리는 대표가 "진행" 한 계획 그대로 7·8단계(기다리는 말씀·헌법·세션 규칙·책임자 넷 뒤)** 로 둘까요, 아니면 그 넷 앞으로 당겨 지금 진행 중인 것(나래 이름표·결재 카드·대시보드 새 설계) 바로 뒤에 둘까요? — 세라 지적: 당기면 대표 순서가 바뀌는 것이라 단추에 드러낸다. 나래 권고: 계획대로 뒤에(재료 5·6단계가 먼저 있어야 선이 그려진다).
- Agent Flow 는 지금 켜져 있습니다(대표 컴퓨터 크롬에서 `http://localhost:3001`, 폰은 안 됨). 보신 뒤 끄고 설정 여섯 줄을 지우고 원래 파일로 되돌리겠습니다(파일 복사).
