# 토론 주제 11 — 화면 "글자 폭탄" 걷기·프로젝트와 요청 규격 (나리 안 1판, 2026-09-18 16:1x)

대표 원문 둘(비서실 16:04 evt_15c0c3a6aa 전문 1,376자 · 16:1x "화면이 더러운 진짜 이유"). 뿌리는 대표가 짚은 그대로 — **화면이 에이전트의 자유 문장을 그대로 뿌린다. 칸을 고정하면 화면은 칸만 그린다.**

## 1. 대표 글자가 정본이다 — 셋의 안이 아니라 규격으로 받는다
- 제목 **30자**, 한 줄 요약 **60자**, 넘으면 **에이전트가 다시 쓴다**(자르지 않는다).
- 상태는 **고정값 배지**: 진행 · 막힘 · 검수 대기 · PASS · FAIL(대표 글자). 우리 보드 여섯(대기·진행·감사 대기·통과·막힘·안 함)과 맞추는 표는 하영 몫 — 통과=PASS, 감사 대기=검수 대기, FAIL 은 반박 셋 뒤 못 씀, 대기·안 함은 배지 없이 목록 밖.
- 담당·단계(n/N)·경과 시간·토큰은 **수와 아이콘**. 설명·경로·커밋 해시는 **눌렀을 때 상세 패널**에만.
- 부품 **넷**: 프로젝트 카드 · 요청 행 · 에이전트 칩 · 상태 배지 — 다섯 화면이 이 넷으로.
- 요청 규격: 요청 사항은 **한 줄**, 배정은 **[마케팅 하영 ➔ 개발 테라]** 배지, 끝나면 결과물이 **칩**으로.

## 2. 칸 고정 = 자료 규격 (솔라) — 화면보다 앞
`state/work.json` 항목과 `state/requests/*.jsonl` 에 칸을 고정한다: `title`(≤30) · `summary`(≤60) · `status`(다섯 중 하나) · `owner` · `stage`(n/N) · `startedAt/doneAt`(경과) · `tokens` · `outputs[]`(칩) · `details`(긴 글 전부 — 화면 첫 판엔 안 나감). 지금 `what` 한 칸에 문단이 들어가던 것을 `title`+`summary`+`details` 셋으로 가른다. 요청도 같은 꼴 + `from`/`to`.

## 3. 자 = "넘으면 다시 쓴다" (하영 규칙 · 솔라 검사 · 유진 셈)
- 자는 지금의 bossOk(하네스 낱말·60자)에 **제목 30자**와 **칸 넘침**을 더한다 — 넘으면 화면에 "숨김 N줄"이 아니라 **에이전트에게 되돌려 다시 쓰게** 한다(대표 글자). 카드·요청을 올리는 명령이 넘치는 줄을 거부하면 사람이 그 자리에서 고친다.
- 하영: 규정집 3판에 "제목 30·요약 60·다시 쓰기" 규칙 한 절 + 보드 116건 `what` → `title`/`summary` 다시 쓰기(J32 뒤 같은 손).
- 유진: 매일 "칸 넘침 0 / 자유 문장 0" 수 한 줄(얼마나-됐나.md 7절).

## 4. 세라 안 공격 둘
- 부품 **셋**이 아니라 **넷** — 프로젝트 카드가 빠졌다(대표: 프로젝트 카드·요청 행·에이전트 칩·상태 배지).
- 상태 배지 "보드 여섯"이 아니라 **대표 다섯** — 여섯을 다섯으로 접는 표를 하영이 한 줄로.
