# ppanam — 마케팅팀 AI 오케스트레이션 + 실시간 단톡방

## Context

`donghyuk44/ppanam` 은 커밋이 하나도 없는 **완전히 빈 저장소**다. 사용자가 의도적으로
백지에서 시작했다.

유튜브 영상 4편을 분석해 "이렇게 일하고 싶다"는 그림을 확정했다. 그런데 분석 결과
**가장 중요한 사실 하나가 드러났다.**

> **페이퍼로지 75분 영상에는 구현 방법이 없다.**
> 패스트캠퍼스 유료 강의 유입용 무료 특강이고, 내용의 대부분은 "왜 클로드 코드로
> 넘어와야 하는가 + 되는 것들 데모"다. CLAUDE.md 실제 내용, 서브에이전트 정의,
> 슬래시 커맨드, 훅, settings.json, 웹 UI 기술 스택, **AI 발언이 채팅창에 실시간
> 반영되는 경로(웹소켓/폴링/파일감시 중 무엇인지)** — 전부 화면에 나오지 않는다.
> 발표자는 1:11:18에서 *"이거 만드는 법이 강의에 있지 않아요"* 라고 직접 말한다.
> 영상에 등장하는 유일한 "제작 방법"은 **"말로 시키면 된다"** 이다.

따라서 이 계획은 영상을 베끼는 것이 아니라, **영상이 보여준 결과물을 우리가 직접
설계해서 재현하는 것**이다. 영상에서 확인된 사실은 근거로 쓰고, 비어 있는 자리는
영상 ③④가 제공한 원칙으로 채운다.

## 설계 판단 — 영상보다 나은 선택 하나

영상 ①이 **구글 계정을 2개 파서 클로드를 2마리 띄운** 이유는 명확하다:
CLAUDE.md가 프로젝트당 하나뿐이라 페르소나가 **동화되기 때문**이다 (53:54).

**그런데 Claude Code 서브에이전트는 각자 독립된 시스템 프롬프트를 갖는다.**
즉 영상이 계정 분리로 우회한 문제를 서브에이전트가 구조적으로 해결한다.

| | 영상 방식 | ppanam 방식 |
| --- | --- | --- |
| 클로드 2인 | 구글 계정 2개 + 로그인 2번 | `.claude/agents/` 서브에이전트 2개 |
| 페르소나 동화 | 계정 분리로 회피 | 서브에이전트별 독립 프롬프트 |
| 요금 | 구독 2배 | 1개 |
| 초대 | 사람이 매번 "초대해 줘" | 라운드 시작 시 자동 |

GPT(코덱스)만 진짜 외부 프로세스이므로 어댑터로 붙인다.

## 아키텍처

### 1. 캐스트 — ALTER 5역을 3인에 접기

영상 ④의 다섯 역할(Advisor / Librarian / Tutor / Editor / Roommate)을 3인에 접는다.
**GPT를 룸메이트 자리에 놓는 것이 핵심**이다. 영상 ④의 룸메이트는 *"낯선 사람의
렌즈(a stranger's lens)"* 를 건네는 역할인데, **다른 모델이야말로 문자 그대로 다른
렌즈**다. 영상 ①에서 클로드가 스스로 *"완전히 다른 엔진을 초대하라"* 고 제안한 것과
정확히 같은 논리에 도달한다.

| 캐스트 | 실체 | 흡수한 ALTER 역할 | 하는 일 |
| --- | --- | --- | --- |
| **실무** | Claude 서브에이전트 | Advisor + Librarian | 킥오프 인터뷰로 로드맵을 짜고, 스코프를 방어하고, 실제 작업을 실행 |
| **내부감사** | Claude 서브에이전트 | Tutor + Editor | "이해한 척"을 못 하게 캐묻고, 산출물의 논리·구조·표현을 감사 |
| **외부감사** | codex CLI (외부 프로세스) | Roommate + 기술감사 | 다른 모델의 렌즈로 교차검증. 클로드 둘이 같이 틀린 지점을 잡음 |

캐릭터 이름·아바타·말투는 Phase 1(디자인)에서 정한다. 영상 ①에서 AI가 스스로
"가우라브 프라카시 티와리"(이니셜 G.P.T)를 지은 것처럼, 작명도 맡길 수 있다.

### 2. 로드맵 엔진 — 영상 ④를 그대로 이식

영상 ④의 **5단계 결정**이 프로젝트 킥오프 산출물이 된다.

| 영상 ④ (학습) | ppanam (업무) |
| --- | --- |
| **Destination** — 다 배웠을 때 뭘 할 수 있나 | Definition of Done. 기능 목록이 아니라 **획득 능력**으로 서술 |
| **Baseline** — 지금 어디에 있나 | 현행 자산·역량 인벤토리 |
| **Sequencing** — 어떤 순서로 (*영상이 유일하게 "정말 중요하다"고 강조*) | 의존성 순서 / 크리티컬 패스 |
| **Cut list** — 지금은 무시할 것 | Out of Scope 명문화. 부록이 아니라 **본문에** |
| **Milestones** — 마스터를 증명할 **내가 만든 산출물** | 주차별 게이트. 완료율 %가 아니라 **제출 가능한 물건** |

**킥오프 방식도 그대로 가져온다.** 영상 ④의 결정적 지시는
*"First, interview me to find my weaknesses, my baseline"* 과
*"Ask me up to five questions for each of these five steps, one question at a time."*
→ **계획서를 먼저 쓰지 않는다. 5단계 × 최대 5문항, 한 번에 하나씩 인터뷰한다.**

이 구조는 이미 설치된 **`wayfinder` 스킬**과 그대로 겹친다 (Destination / Notes /
Decisions so far / Not yet specified / Out of scope). 영상 ③이 추천한 스킬과 영상 ④의
방법론이 같은 곳에 도착한다 — **킥오프는 `wayfinder`로 돌린다.**

### 3. 라운드 — 영상에 없는 것을 우리가 채운다

영상 ①에는 라운드도 리셋도 없다. 흔적은 *"3번 반박 받아줘"* 협상 한 장면뿐이다.
그래서 이 부분은 우리 설계다.

- **마일스톤** = 로드맵의 한 주차. 통과 조건은 **산출물 시연** (영상 ④의 원칙).
- **라운드** = 마일스톤 하나를 향한 한 번의 작업 사이클:
  `실무 실행 → 내부감사 감사 → 외부감사 교차검증 → 판정`
- **판정 3종**: `PASS`(다음 마일스톤) / `REVISE`(같은 마일스톤 재라운드) / `FAIL`(사람 호출)
- **반박 상한**: 라운드당 최대 3회. 영상 ①의 "3번 반박" 협상 장면에서 가져온다.
  상한에 걸리면 자동 `FAIL` → 사람이 판단. 무한 논쟁 방지.
- **라운드 종료 = 채팅창 초기화 + 기록 보관.**

> 영상 ④는 **마일스톤 실패 시 재시도 규칙을 다루지 않는다.** 위 3판정 + 반박 상한이
> 그 공백에 대한 우리 답이다.

### 4. 감사 기준 — 영상 ④에서 그대로 옮긴 체크리스트

**내부감사(Editor) 5개 항목:** ① 논리에 반론을 제기하라 ② 논증의 약점을 찾아라
③ 반복을 잘라내라 ④ 구조를 조여라 ⑤ 언어를 더 정확하고 구체적으로 만들어라

**스코프 트리아지 4쌍(Librarian):** ① 이 스코프에 속하는가 ② 출처가 신뢰 가능한가
③ 현재 역량 대비 너무 앞서는가 ④ 신호인가 잡음인가

**내부감사의 질문 규칙(Tutor):** 한 번에 한 질문 / 설명하지 말 것 / 갭을 찾을 것 / 정확할 것.
목표는 *"이해한 척을 하기 어렵게 만드는 것"*.

이 셋을 `teams/marketing/rubric.md` 에 둔다. 프롬프트가 아니라 파일이다.

### 5. 실시간 단톡방 — 영상이 감춘 부분을 공식 문서로 채운다

영상 ①에는 실시간 반영 경로가 전혀 나오지 않는다. 그래서 Claude Code 공식 문서를
조사해 확정했다. **결정적 발견 3가지:**

**① `SubagentStop` 훅이 발언 본문을 직접 준다.**
훅 stdin JSON에 `last_assistant_message`(발언 전문), `agent_type`(화자 = 서브에이전트의
`name`), `agent_id`(스레드 키)가 들어 있다. 즉 말풍선에 필요한 3요소가 그대로 온다.
문서는 transcript 파일을 읽지 말라고 **명시적으로 권고**한다 — 비동기로 기록돼 현재 턴이
아직 안 들어 있을 수 있고, 라인 스키마는 *"internal to Claude Code and changes between
versions"* 라 버전마다 깨진다.

**② 훅이 HTTP를 직접 쏠 수 있다.**
`type: "http"` 훅은 문서화된 1급 기능이다. 파일을 tail할 필요 없이 훅이 Node 서버로
바로 POST한다.

**③ `--forward-subagent-text` 로 생성 중 텍스트가 흘러나온다.**
`claude -p --output-format stream-json --verbose --include-partial-messages
--forward-subagent-text` 조합이면 서브에이전트의 텍스트가 토큰 단위(`text_delta`)로
나오고, `parent_tool_use_id`가 `null`이면 메인, 값이 있으면 그 서브에이전트다.
**타이핑되는 말풍선**이 가능하다는 뜻이다. (v2.1.211+ 필요, 중첩은 v2.1.219+. 현재 2.1.252)

**채택: 3채널 조합**

| 채널 | 수단 | 역할 |
| --- | --- | --- |
| **표시** | `-p --output-format stream-json --forward-subagent-text` | 생성 중 텍스트 → 타이핑 말풍선 |
| **제어** | `SubagentStop` 훅 (`type: http`) | 발언 완료 확정 + **반려**(exit 2 / `decision:"deny"`)로 감사 루프 |
| **기록** | 훅 (`type: command`, `async: true`) → JSONL append | 감사 로그 · 라운드 보관 · 리플레이 |

기록 채널을 파일로 남기는 이유는 그대로다: **라운드 종료 시 파일을 보관 후 비우면
채팅창이 자동 초기화**되고, 영상 ①의 오케스트레이션 정의 — *"백단에 코드 같은
덩어리들로 얘기한다"* — 와도 부합한다.

**주의 (문서 근거):**
- 매칭되는 훅은 **전부 병렬 실행**된다 → JSONL append는 단일 write(O_APPEND)로 원자화해야
  줄이 섞이지 않는다.
- 훅 기본 타임아웃이 **600초**다. 서버가 죽으면 세션이 멈춘다 → `async: true` 또는
  짧은 `timeout`을 반드시 지정한다.
- **`--bare` 는 훅을 로드하지 않는다.** 이 설계에서 `--bare`를 쓰면 아무것도 기록되지
  않는다. 그런데 문서는 이것이 *"will become the default for `-p` in a future release"*
  라고 예고한다 → 버전 올릴 때 반드시 회귀 테스트.
- `Stop`과 `UserPromptSubmit`은 matcher를 지원하지 않지만 **`SubagentStop`은 지원**한다
  → 에이전트별로 다른 훅을 걸 수 있다.
- 서브에이전트 `.md` frontmatter의 **`color`** 필드가 공식 필드다 → 말풍선 색을
  에이전트 정의 파일에 함께 둔다. 별도 매핑 설정이 필요 없다.

**호스팅은 로컬 서버.** 영상 ①이 실제로 그렇게 한다(1:13:08). 폰에서 볼 필요가 생기면
그때 Tailscale을 붙인다 — 영상과 같은 경로다. 지금 인증·DB·배포를 만들지 않는다.

### 6. 방(room) 구조

영상 ① 수강생 사례(1:08:24)에서 1:1 방과 그룹 방이 분리돼 있었다. 이걸 가져오되
지금은 단순하게 간다:

- **작전실** (기본) — 3인 전원 + 사람. 라운드가 여기서 돈다.
- 팀이 늘어나면 팀별 채널로 확장 (마케팅 / 개발 / 문서 / 재무).

## 실행 순서

사용자 요청대로 **디자인을 먼저** 잡는다. 다만 시안을 그리려면 화면에 무엇이 나타나는지
어휘가 먼저 정해져야 하므로, 종이 위 작업 한 단계를 앞에 둔다.

### Phase 0 — 정리와 어휘 확정
1. 계획 이전에 만든 습작 파일을 **전부 삭제**한다 (아래 "정리 대상"). 백지에서
   시작한다는 사용자 의도를 지킨다.
2. `docs/event-schema.md` 한 장으로 **이벤트 어휘**를 고정한다 — 채팅방에 나타날 수 있는
   것의 전체 목록: `말풍선` / `시스템 배너` / `판정 카드(PASS·REVISE·FAIL)` /
   `도구 사용 로그` / `사람 발언` / `마일스톤 진행 표시`.
   디자인과 구현이 같은 것을 보게 만든다.

### Phase 1 — 채팅방 디자인 (`/design`) ★ 사용자 승인 지점
`/design` 스킬로 아트보드 캔버스를 만든다. 최소 4장:
- **작전실 기본** — 3인 말풍선, 아바타, 라운드 배너
- **판정 순간** — 내부감사·외부감사가 REVISE를 낸 화면
- **라운드 전환** — 화면이 비워지고 다음 마일스톤이 시작되는 순간
- **로드맵 패널** — 마일스톤 진행 상황

`impeccable-design` 스킬을 함께 적용한다(영상 ③ 추천). 이 스킬의 핵심 경고는 "AI가
무의식적으로 반복하는 기본값 — Inter 폰트, 보라-파랑 그라디언트, 카드 안의 카드,
제목마다 둥근 아이콘 타일 — 을 의도적으로 피하라"는 것이다.
아이메시지를 출발점으로 삼되(영상 ① 18:01) 거기서 그치지 않는다.

**사용자가 캔버스에서 직접 다듬고 확정한 뒤 Phase 2로 간다.**

### Phase 2 — 이벤트 버스 + 실시간 서버
- `bus/` — 이벤트 append / 라운드 시작·종료·보관 CLI
- `server/` — 파일 tail → WebSocket 중계, 지난 라운드 열람
- Phase 1 시안을 실제 화면으로 구현
- 의존성 최소 (Node 22 내장 + WebSocket 라이브러리 하나)

### Phase 3 — 하네스 (캐스트 + 라운드)
- `.claude/agents/` — 실무 / 내부감사. 각각 `name`(= 훅이 받는 `agent_type`)과
  `color`(말풍선 색)를 지정한다. 말투·인격은 **서브에이전트 본문**에 쓴다
  (output style은 서브에이전트에 적용되지 않으므로).
- `.claude/commands/` — `/kickoff` `/round` `/verdict`
- **훅** — 에이전트 발언과 도구 사용이 **자동으로** 버스에 흘러가게 한다.
  에이전트가 "버스에 쓰는 것을 기억해야" 하면 반드시 빠뜨린다. 훅이 대신한다.
  - `SubagentStop` → `agent_type` + `last_assistant_message` 를 말풍선으로
  - `SubagentStart` → "등장" 배너
  - `PreToolUse`/`PostToolUse` → 접힌 도구 로그
  - `UserPromptSubmit` → 사람 말풍선
- **감사 반려 루프**: `SubagentStop` 훅에서 `decision: "deny"` + `reason` 을 돌려주면
  그 서브에이전트가 멈추지 못하고 계속 일한다. 이것이 "내부감사가 실무를 되돌려보내는"
  메커니즘의 실제 구현이다. 반박 상한 3회는 훅 쪽에서 카운트한다.

### Phase 4 — 외부감사(GPT) 연결
공식 문서 조사 결과, 외부 모델을 붙이는 경로가 3가지다. **MCP 서버로 감싸는 것이 가장 낫다.**

| 경로 | 장점 | 판단 |
| --- | --- | --- |
| **GPT를 MCP 서버로** (`.mcp.json`) | 서브에이전트 frontmatter의 `mcpServers` 로 **외부감사만 접근**하게 제한 가능 | **채택** |
| `type: "mcp_tool"` 훅 | GPT를 훅 레이어의 감시자로 직접 배치 | 2순위로 병행 |
| codex CLI 자식 프로세스 | 영상 ① 방식과 동일 | 대안으로 남김 |

- ✅ 로컬에서 연결 검증 완료. `npm run outside -- --check` 가 실제 답을 돌려준다.
  호출 형태는 `codex exec --ephemeral --skip-git-repo-check -o <파일> -` 이고,
  프롬프트는 stdin 으로 넘기되 **파이프를 닫아야** 한다(부록 B).
- GPT가 없으면 자동 비활성 → 클로드 2인으로 라운드가 돌게 한다(graceful degradation).
- 참고: 서브에이전트끼리는 **`SendMessage`** 로 직접 대화할 수 있다. 단 sibling roster는
  **서브에이전트 시작 시점의 스냅샷**이라, 서로를 보게 하려면 **대화 시작 전에 참여자를
  모두 spawn** 해야 한다. 라운드 설계에서 순서상 중요한 제약이다.

### Phase 5 — 로드맵 엔진
- `/kickoff` 가 `wayfinder` 방식으로 5단계 × 최대 5문항 인터뷰를 돌려 `roadmap.md` 생성
- 마일스톤 게이트 판정과 진행 상태 관리

### Phase 6 — 마케팅팀 채우기
마케팅팀 캐스트 인격·rubric·첫 로드맵을 실제로 채우고 **라운드를 한 번 완주**한다.
여기까지가 "검증된 한 팀"이다. 다른 부서 복제는 그 다음이다.

### Phase 7 — 스킬 정비 (영상 ③)
- `impeccable-design`, `wayfinder` — 이미 설치돼 있으나 **축약된 chat 전용판**이다.
  원본이 필요하면 각 SKILL.md 에 적힌 설치 명령을 쓴다

- `i-have-adhd`(토큰 절약), `Aside`(브라우저 검색) — 미설치. **여기까지 미룬다.**

## 검증 방법

- **Phase 1**: 아트보드 캔버스를 사용자가 직접 열어 확인하고 승인한다.
- **Phase 2**: 서버를 띄운 채 터미널에서 발언 CLI를 몇 번 호출해, 브라우저에 말풍선이
  **새로고침 없이** 나타나는지 본다. 라운드 종료 명령으로 화면이 **자동으로 비워지고**
  기록이 `rounds/` 에 남는지 확인한다.
- **Phase 3**: 실제 작업 하나를 라운드로 돌려, 에이전트 발언이 **훅에 의해 자동으로**
  채팅방에 흐르는지 확인한다. 수동 호출 없이 흘러야 통과.
- **Phase 4**: 양쪽을 다 본다. ✅ 연결된 상태에서 실제 답이 오는 것, 그리고 PATH 에서
  codex를 뺐을 때 **판정하지 않고** "설정 안 됨"으로 물러나며 exit 1 하는 것 — 둘 다 확인했다.
  남은 것: 클로드 둘이 통과시킨 산출물을 codex가 반려하는 사례를 1건 만든다.
  이 케이스가 나와야 교차검증이 실제로 작동한다는 증거다.
- **Phase 5**: `/kickoff` 로 마케팅 프로젝트 하나의 로드맵을 뽑고, 5단계 결정이 모두
  채워졌는지, **cut list가 비어 있지 않은지** 확인한다.
- **Phase 6**: 마일스톤 하나를 라운드로 완주 — PASS 또는 REVISE 판정이 실제로 나오는지.

## 부록 A — 실물 검증 결과

문서에서 확정하지 못했던 것들을 로컬에서 훅을 걸어 stdin JSON 을 덤프해 확인했다
(`PPANAM_HOOK_DEBUG=1` → `.claude/hooks/payload-<이벤트>.json`).
검증 환경: macOS / Claude Code / codex-cli 0.151.0.

### 확인 완료 — 추측이 맞았다

**1. `PostToolUse` 의 툴 결과 필드명 = `tool_response`** ✔
단, **문자열이 아니라 객체**다. 모양은 도구마다 다르다. `Read` 의 경우:

```json
"tool_response": { "type": "text",
  "file": { "filePath": "…", "content": "…", "numLines": 1, "startLine": 1, "totalLines": 87 } }
```

같은 payload 에 `duration_ms` 도 함께 온다.

**2. `UserPromptSubmit` 의 프롬프트 텍스트 필드명 = `prompt`** ✔
동봉 필드: `session_id` / `transcript_path` / `cwd` / `prompt_id` / `permission_mode` /
`hook_event_name`.

**3. `SubagentStart` 전체 스키마** ✔ — 7개뿐이다.
`session_id` / `transcript_path` / `cwd` / `prompt_id` / `agent_id` / `agent_type` /
`hook_event_name`. 발언 본문은 없다(당연히 아직 말하기 전이다).
`SubagentStop` 은 여기에 `permission_mode` / `effort` / `stop_hook_active` /
`agent_transcript_path` / `last_assistant_message` / `background_tasks` / `session_crons`
가 더 붙는다. **`agent_id` 가 시작과 종료에서 동일**하므로 스레드 키로 쓸 수 있다.

### 아직 미확인 (실물로 확인할 기회가 없었다)

4. JSON 출력의 `continue` 필드. 확인된 제어 필드는
   `decision` / `reason` / `stopReason` / `suppressOutput` / `permissionDecision` /
   `additionalContext` / `systemMessage` / `updatedInput` / `retry`.
5. `stream-json` 의 전체 메시지 타입 목록. 확인된 것: `stream_event`, `system/init`,
   `system/api_retry`, `result`, `assistant`, `user`,
   `hook_started`/`hook_progress`/`hook_response`.

## 부록 B — 함정

### `async: true` 를 종료 훅에 쓰면 마지막 발언이 사라진다 ★ 실물로 당함

`Stop` 훅에 `"async": true` 를 걸면 **실무의 마지막 발언이 대화록에 남지 않는다.**
`claude -p` 세션 7회 중 6회 유실했다. 남은 1회는 맨 처음 세션이라, 간헐이 아니라
**경합에서 거의 항상 지는 쪽**으로 보는 게 맞다. 고친 뒤에는 4회 중 4회 기록됐다.

증상이 고약한 이유는 훅이 **실패한 것처럼 보이지 않기** 때문이다.
payload 덤프는 정상적으로 파일에 쓰이고, `bail()` 도 타지 않는다. 훅 프로세스가
덤프 직후 `bus.emit()` 에 닿기 전에 회수된다. 세션은 조용히 끝나고 대화록만 비어 있다.
같은 payload 를 손으로 먹이면 정확히 emit 되므로 스크립트를 아무리 봐도 원인이 안 보인다.

fire-and-forget 훅은 세션이 살아 있는 동안에만 안전하다. 그래서 이렇게 나눈다.

| 훅 | 시점 | 설정 |
| --- | --- | --- |
| `UserPromptSubmit` · `SubagentStart` · `PostToolUse` | 세션 중간 | `async: true` — 세션을 막지 않는다 |
| `Stop` · `SubagentStop` | 종료 경계 | **동기 + `timeout: 10`** |

`Stop` 은 라운드의 결론을, `SubagentStop` 은 감사 판정을 나른다. 이 둘이 유실되면
`/verdict` 가 감사할 대상 자체가 대화록에 없다. 동기로 돌리되, 훅이 멈춰도 세션이
잠기지 않도록 짧은 `timeout` 을 명시한다(기본값은 600초라 지정하지 않으면 위험하다).

### 그 밖

- 슬래시 커맨드 인자는 **0-based**다. `$0`이 첫 번째, `$1`이 **두 번째**. bash 관례와 다르다.
- 훅 스크립트에서 셸 프로필(`.bashrc`)의 `echo` 출력이 stdout 앞에 섞이면
  JSON이 통째로 무시된다. 출력이 `{` 로 시작하지 않으면 plain text로 처리된다.
- `SessionEnd` 훅은 **공유 1.5초 예산**이다. 종료 시 flush하려면 `timeout`을 명시적으로 올려야 한다.
- 커스텀 슬래시 커맨드는 **Skills로 통합**됐다. `.claude/commands/*.md` 는 계속 동작하지만
  frontmatter 스키마는 SKILL.md 와 같다.
- `claude --bare` 는 훅을 **아예 로드하지 않는다.** 문서가 이것을 `-p` 의 미래 기본값으로
  예고했으므로, Claude Code 버전을 올릴 때마다 훅 실동작을 재확인한다.
- `codex exec` 에 프롬프트를 stdin 으로 넘길 때 **파이프를 반드시 닫아야 한다.**
  `execFile` 로 부르면 stdin 이 열린 채라 codex 가 입력을 영원히 기다린다
  (`bus/outside.mjs` 는 `spawn` + `stdin.end()` 로 처리).
